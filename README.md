# Phase 0: Heterogeneous Indian corridor and sublane-seepage evidence

This phase **only** creates the network and demand, then runs the unmodified fixed-time signal plan (P0). It does **not** implement or evaluate preemption/recovery controllers yet.

## Prerequisites
- Install Eclipse SUMO with `sumo`, `sumo-gui`, and `netconvert` available in `PATH`.
- Python >= 3.10.
- `python -m pip install -r requirements.txt`.
- On systems where TraCI is not pip-installed, set `SUMO_HOME` to the SUMO installation folder.

## Run
```bash
python run_phase0.py --gui --share 0.55 --flow high --seed 42
```
For a headless run:
```bash
python run_phase0.py --share 0.55 --flow high --seed 42
```
For a short smoke test:
```bash
python run_phase0.py --gui --limit 120
```
A headless run requires the `sumo` executable; a GUI run requires `sumo-gui` and a desktop display.

## Scenario
- Five signalized crossroad intersections (`J1` through `J5`) and a bidirectional six-link east/west corridor with three lanes per direction.
- Side approaches enter each signalized junction, with Poisson generated demand.
- Left-hand traffic, fixed-time traffic lights generated by `netconvert`.
- 0.3 m lateral resolution, 0.2 s step length, and SL2015 vehicle sublane changing.
- Vehicle types: two-wheeler, car, auto-rickshaw, bus, truck, ambulance.
- One ambulance (`EV_001`) departs from the west edge and traverses every signal on the eastbound corridor.
- Scenario variants: `--share 0.10` to `--share 0.80`, `--flow low|medium|high`, `--seed N`.
- Traffic flows in `config.py` are **input demand**, not guaranteed discharge rates.

## Visual check in SUMO GUI
1. Start with `--gui --flow high --share 0.7`.
2. Zoom into eastbound approach of `J2` or `J3` while the signal is red.
3. Identify orange two-wheelers and blue cars. The motorcycles should show **non-centred lateral positions**, and may advance through available lateral gaps while cars are stationary.
4. Use SUMO's vehicle inspector to observe `posLat` (lateral lane position), or inspect `results/positions.csv`.
5. Inspect `results/seepage_events.csv` for **conservative same-lane order-reversal events**. These are stronger indicators than nonzero lateral offsets alone.

## Outputs
- `build/corridor.net.xml`: compiled network with fixed-time TLS logic.
- `build/demand.rou.xml`: seeded vTypes, routes and vehicles.
- `build/departures.csv`: audit of requested departures and vehicle classes.
- `results/positions.csv`: time-stepped trajectory with lane, longitudinal and lateral position.
- `results/signals.csv`: every signal state at every step.
- `results/seepage_events.csv`: motorcycle/car overtakes detected within the same lane and edge.
- `results/seepage_summary.json`: offset and passing counters.
- `results/tripinfo.xml`: SUMO's trip records (completed trips and relevant statistics).

## Validity and limitations
The lane-level order-reversal checker is intentionally conservative. It will **miss** passes involving lane switches or separated observations; nonzero `posLat` does not by itself prove passing. No positive seepage result should be claimed before observing real trajectories. Queue spillback, departures delayed by insertion constraints and microsimulation collisions/teleports must be checked before empirical comparisons. Values are synthetic demonstration assumptions and require field-based calibration before any Indian-traffic generalizability claim. GUI rendering is not a measurement; numeric traces are the reproducible evidence.
